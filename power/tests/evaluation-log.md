# Evaluation log

One row per import. The point is to see whether a build was better or worse than the one before it,
measured the same way every time, rather than judged on how the last screenshot felt.

Who writes what:

- **Build**, **Claim**, **Offline**, **Round trip** — the import unit, at the moment the import
  lands. `node scripts/log-eval.mjs --build ... --claim ... --offline ... --roundtrip ...` writes
  them; a later unit has `import-app.mjs` call it automatically.
- **Studio** — the orchestrator, from what Craig pastes out of the App checker: `opened clean`, or
  the error count with its codes. `node scripts/log-eval.mjs --studio "..."`.
- **Player** — the orchestrator, from what Craig reports after using the app, one line.
  `node scripts/log-eval.mjs --player "..."`.
- **Verdict** — the orchestrator, comparing this row with the one above it on two numbers only:
  Studio errors, and defects Craig reported. Better, same or worse.

`not checked` means nobody looked, and is never the same as `clean` or `none`.

Solution and data imports are not rows here; they carry no canvas build. Times are UTC, as the
session recorded them.
